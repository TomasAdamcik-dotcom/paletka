# Desktop Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GNOME Shell 50 extension that switches whole-desktop theme families (Ubuntu, Solarized, user-made) from a Quick Settings tile, with a built-in editor.

**Architecture:** Pure GJS modules generate all artifacts (GTK4/GTK3/shell CSS, terminal palettes, wallpaper SVG) from a family JSON; an `Applier` orchestrates writes through injected settings/fs/services adapters (unit-tested with fakes); `extension.js` hosts the tile and loads the shell stylesheet; `prefs.js` is the Adw editor. E2E runs a headless nested gnome-shell in an isolated XDG/dconf environment.

**Tech Stack:** GJS 1.88 (ESM), GNOME Shell 50 extension API, GTK 4.22 / libadwaita 1.9 (prefs), Gio/GLib, bash + `dbus-run-session` for E2E. No npm deps.

**Spec:** `docs/superpowers/specs/2026-11-02-desktop-themes-design.md`

## Global Constraints

- UUID `desktop-themes@adamciktomas.github.io`; `shell-version: ["50"]`; `session-modes: ["user", "unlock-dialog"]`; gettext domain `desktop-themes`; settings schema `org.gnome.shell.extensions.desktop-themes`.
- ESM only (`import … from 'gi://…'`, `resource:///org/gnome/shell/…`, `resource:///org/gnome/Shell/Extensions/js/…` in prefs).
- `extension/lib/{color,palette,model,gtkCss,shellCss,terminal,wallpaper,accent}.js` import nothing but each other (and `gi://GLib` if needed) — they must run under plain `gjs -m`.
- No network access at runtime. No writes outside `$XDG_CONFIG_HOME`, `$XDG_DATA_HOME`, `$XDG_CACHE_HOME`.
- Every file we generate starts with `GENERATED_HEADER` = `/* Generated by Desktop Themes — do not edit. */` (CSS) or `# Generated by Desktop Themes — do not edit.` (palette INI); SVGs get `<!-- Generated by Desktop Themes -->`.
- User themes: `$XDG_CONFIG_HOME/desktop-themes/themes/<id>.json`. Backup: `$XDG_DATA_HOME/desktop-themes/backup/`. Shell CSS: `$XDG_CACHE_HOME/desktop-themes/shell-<id>-<light|dark>.css`. Wallpapers: `$XDG_DATA_HOME/backgrounds/desktop-themes/<id>-<light|dark>.svg`.
- Built-in ids `ubuntu` (kind `system`) and `solarized` (kind `custom`) are read-only.
- `disable()` never reverts gsettings or gtk.css.
- UI strings in English via gettext, Slovak translation `po/sk.po`.
- Unit tests: `gjs -m tests/run.js` must exit 0. E2E: `tests/e2e/run.sh` must exit 0 and never touch the real session (isolated XDG dirs, own dbus, `restart-background-services=false`).

## Review Focus

1. Hand-edited/malformed user theme JSON (bad hex, missing variant, wrong version) → that family is skipped with a logged warning; all others still load; the tile still works. (Task 6 test `store skips invalid files`.)
2. Pre-existing user `gtk.css` not written by us (the user has one today) → backed up on first custom apply and restored byte-identical on switching to Ubuntu; a file the user edited after we wrote ours (no header) is never deleted. (Task 7 tests `restore puts back foreign gtk.css byte-identical`, `restore keeps file without our header`.)
3. Lock/unlock = disable/enable cycles → exactly one tile and at most one loaded custom stylesheet afterwards, no errors. (Task 11 E2E step `disable-enable twice`.)
4. Active family deleted or renamed on disk while active → resolve to `ubuntu` and restore, never crash. (Task 2 test `resolveActiveId falls back to ubuntu`; Task 9 wiring.)
5. Missing optional pieces (no Ptyxis schema, no GNOME Terminal profile, icon theme not installed, wallpaper file missing) → that step is skipped silently, others applied. (Task 7 test `apply skips missing terminals and unknown icon theme`.)
